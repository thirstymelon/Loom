Setup & Installation Guide

Getting started with Loom

A complete guide to installing the Loom v1.1.0 toolchain, configuring your development environment, setting up VS Code, understanding workspace anatomy, and building your first native application.

Installing Loom

Loom is distributed as a self-contained toolchain containing the workspace manager (loom), the native compiler (loomc), the Loom Software Development Kit (SDK), and the official VS Code extension.

macOS (Apple Silicon M1/M2/M3/M4)

Loom provides two specialized Apple Silicon installer packages (.pkg) depending on your development workflow:

  • Desktop Native Toolchain (Loom-1.1.0-macos-arm64-native.pkg): For general-purpose macOS desktop applications, high-performance systems utilities, and command-line tools. Installs the universal build driver (loom), native desktop compiler (/usr/local/share/loom/toolchains/native/bin/loomc), standard library (sdk/std/), and VS Code extension.
  • RP2040 Embedded Toolchain (Loom-1.1.0-macos-arm64-rp2040.pkg): For bare-metal Raspberry Pi Pico (RP2040) firmware development. Installs the universal build driver (loom), ARM Cortex-M0+ compiler (/usr/local/share/loom/toolchains/rp2040/bin/loomc), automatic UF2 packager, full 16-peripheral RP2040 HAL/BSP (sdk/targets/rp2040/), Boot2 loader, linker scripts, and VS Code extension.

Both packages install side-by-side into /usr/local/share/loom/toolchains/ without overwriting one another. You can switch the active toolchain anytime:

# View installed toolchains and active default
loom toolchains

# Switch default toolchain
loom use rp2040
loom use native

# Per-build override
loom build --toolchain rp2040

Linux & Unix Environments

On Linux systems, extract the Loom release bundle to your system root:

sudo cp bin/loom bin/loomc /usr/local/bin/
sudo chmod +x /usr/local/bin/loom /usr/local/bin/loomc
sudo mkdir -p /usr/local/share/loom/sdk
sudo cp -Rf sdk/* /usr/local/share/loom/sdk/

Verify Toolchain Installation

Confirm that both the compiler and workspace driver are accessible from your PATH:

loom --version     # loom 1.0.0
loomc --version    # loomc 1.0.0 (LLVM 23.1.4)

Toolchain architecture

The Loom toolchain consists of four integrated components designed to work together without external package managers:

ComponentExecutable / PathTechnical Role & Function
Loom DriverloomWorkspace coordinator. Handles project creation (loom new), dependency resolution, incremental build management, UF2 embedded firmware packaging, and dependency graph generation.
Loom CompilerloomcNative language frontend. Parses Loom source files, performs semantic type checking and bounds analysis, lowers the AST into LLVM IR, runs optimization pipelines, and emits native object files (.o).
System LinkerclangTarget linker. Links compiled Loom object files and C runtime libraries into standalone native binaries, or bare-metal ELF binaries with hardware linker scripts.
Loom SDK/usr/local/share/loom/sdk/Hardware Abstraction Layer (HAL) for microcontrollers (RP2040 Cortex-M0+ BSP), bootloaders (boot.s), linker scripts (linker.ld), and the core standard library (std/math.loom). You can override this path by setting the $LOOM_SDK_PATH environment variable.

VS Code extension & editor setup

The official Loom Language Support extension for Visual Studio Code provides full syntax highlighting, code snippets, real-time diagnostic error highlighting, and interactive dependency graph explorers.

Installing the Extension

To install the packaged VSIX extension from your terminal, run:

code --install-extension /usr/local/share/loom/vscode/Loom-1.1.0.vsix

Alternatively, in VS Code: press Ctrl Shift P (or Cmd Shift P on macOS), type Install from VSIX..., and select Loom-1.1.0.vsix.

Workspace anatomy & configuration

Creating a new workspace with loom new <project-name> generates a clean, standard directory layout:

MyProject/
├── config.toml       # Workspace build configuration
├── README.md         # Documentation
├── .gitignore        # Ignores build artifacts (target/)
└── src/
    └── main.loom     # Main entry point source file

Understanding config.toml

The config.toml file defines the project parameters, sources, compilation flags, and toolchain paths:

[project]
name = "MyProject"
version = "1.0.0"

[build]
main = "src/main.loom"
sources = ["src/*.loom"]
target-dir = "target"
executable = "MyProject"

[toolchain]
clang = "clang"
Configuration KeyTypeDescription
project.nameStringName of the project.
project.versionStringSemantic version string.
build.mainStringPath to the entry source file containing Block Main.
build.sourcesArrayGlob patterns matching all source files to compile (e.g. ["src/*.loom"]).
build.target-dirStringOutput directory for compiled binaries and intermediate object files (default: target).
build.executableStringName of the output binary.
build.baremetalBooleanSet to true for microcontroller targets with no OS runtime.
build.targetStringTarget LLVM triple (e.g. thumbv6m-none-eabi for RP2040).
build.cpuStringTarget CPU core architecture (e.g. cortex-m0plus).
build.uf2-outputBooleanAutomatically convert ELF into flashable Raspberry Pi UF2 image.
toolchain.clangStringPath or executable name for the Clang linker.

Building and running your first project

Let's create, inspect, and run a complete Loom application from scratch:

1. Scaffold the Project

loom new Greeting
cd Greeting

2. Review the Source Code (src/main.loom)

Module Main

Block Main
Implements
    Write("Hello from the Loom systems language!")
End Main

Language Rule: Every Loom source file must start with a Module <Name> declaration. The executable entry point must be a parameterless procedure named Block Main.

3. Build the Project

Compile the project into a native binary inside the target/ directory:

loom build

To compile with full LLVM -O3 optimizations, vectorization, and dead-code stripping, pass the --release flag:

loom build --release

4. Execute the Application

Run the compiled binary directly, or use the loom run shortcut which builds and immediately executes:

loom run

5. Optimization Report

To see detailed insight into loop vectorization, bounds-check elimination, and inlining performed by the compiler:

loom build --release --opt-report

6. Cleaning Build Artifacts

To remove the target directory and all intermediate object files:

loom clean

You are now ready to write Loom code. Head to the hands-on tutorials to learn language syntax, types, loops, procedures, pointers, and memory control.
