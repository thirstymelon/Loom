Developer · RP2040 BSP

RP2040, one block at a time.

Start with the guided examples, then open any function to see its exact Loom signature and a call drawn from the compile-checked walkthrough. This handbook covers all public blocks in the 16 RP2040 BSP modules.

Choose your path. New to Loom? Begin with the blink tutorial. Building a driver? Use this page as the function-by-function reference. The examples are compile checks; they do not prove MMIO behavior on a physical board.

Setup, handles, and failures

Call RP2040_Init() before using peripherals that depend on the Pico clock tree. It configures the reference board's 12 MHz crystal and 125 MHz system/peripheral clocks. GPIO and bus pin assignments must match the board wiring; I²C also needs suitable external SDA/SCL pull-ups.

I2C_Init(SDA, SCL) returns an I2C_Handle; SPI_Init(SCK, MOSI, MISO) returns an SPI_Handle. Pass that value to every operation or library initializer that uses the bus. I²C defaults to 100 kHz; SPI defaults to 1 MHz, eight-bit words, mode 0. Device libraries retain the handle they receive, so initializing a second controller does not silently change the first device's bus.

I²C, SPI, UART, GPIO, SSD1306, and MPU6050 operational failures are handled inside the call: each records a diagnostic code/message and stops at the failure. Inspect the matching *_Last_Error_Message and *_Last_Error_Code globals in a debugger. These messages are not currently emitted to UART. ADC, PWM, DMA, and several lower-level BSP modules retain their documented status/sentinel behavior.

Before testing on a board

  1. Confirm the exact RP2040 board, crystal frequency, power, ground, and logic voltage.
  2. Check the selected UART/SPI/I²C GPIO function mapping against the board wiring and the RP2040 datasheet.
  3. For I²C, confirm the 7-bit device address and suitable external SDA/SCL pull-ups.
  4. Use a logic analyzer or oscilloscope to verify baud rate, SPI mode/clock, I²C START/repeated-START/STOP, and NACK handling under both normal and disconnected-device conditions.

Repository checks compile Loom examples only. They do not execute MMIO or claim hardware timing/electrical validation.

How to use this handbook

  1. Import a module and add use Module to make its blocks available.
  2. Open a function name to read its signature and jump to its full module walkthrough.
  3. Compile the example for the RP2040 target. Before connecting a device, check pin mapping, voltage, pull-ups, and the device datasheet.

Values and constants are shown in each module's compiling fixture. Setup functions should be called before the peripheral is used. Blocking functions may wait for hardware; use them only after the peripheral and wiring are ready.

I²C bus

Choose the SDA and SCL pins. Loom selects the matching RP2040 controller and configures the beginner default speed of 100 kHz.

Simple I²C API

I2C_Init(SDA_Pin: Signed_64, SCL_Pin: Signed_64) → I2C_Handle

Initializes the matching controller with a 100 kHz default and returns a typed bus handle. Keep the handle and pass it to device-library initializers.

Device_I2C = I2C_Init(4, 5)
I2C_Write(Handle: I2C_Handle, Device_Address: Signed_64, Bytes: Unsigned_8 Slice)

Sends a byte slice to a 7-bit device address. Errors are retained in the I²C diagnostic globals and stop at the failed operation.

I2C_Write(Device_I2C, 0x68, Slice(Bytes))
I2C_Read(Handle: I2C_Handle, Device_Address: Signed_64, Bytes: Unsigned_8 Slice)

Reads into the provided byte slice using the supplied bus handle.

I2C_Read(Device_I2C, 0x68, Slice(Bytes))
I2C_Write_Register(Handle: I2C_Handle, Device_Address: Signed_64, Register_Index: Signed_64, Value: Signed_64)

Writes one byte to a device register.

I2C_Write_Register(Device_I2C, 0x68, 0x6B, 0x00)
I2C_Read_Register(Handle: I2C_Handle, Device_Address: Signed_64, Register_Index: Signed_64) → Signed_64

Reads one register byte. Transport failures are handled internally; the returned integer is register data.

Value = I2C_Read_Register(Device_I2C, 0x68, 0x75)
I2C_Read_Register_Block(Handle: I2C_Handle, Device_Address: Signed_64, Start_Register: Signed_64, Bytes: Unsigned_8 Slice)

Reads a consecutive register range in one transaction: a pointer write without STOP, a repeated START, then a read ending with STOP. An empty slice performs no bus operation.

I2C_Read_Register_Block(Device_I2C, 0x68, 0x3B, Slice(Bytes))

Serial communication

Select UART0 or UART1 from the physical TX/RX pin pair. The beginner setup uses 115200 baud, eight data bits, no parity, and one stop bit.

Simple UART API

UART_Init(TX_Pin: Signed_64, RX_Pin: Signed_64) → UART_Handle

Initializes the matching UART and returns a typed handle. Keep it and pass it to all UART calls.

Serial = UART_Init(0, 1)
UART_Write(Handle: UART_Handle, Text: String)

Writes a string. Invalid handles and transmit timeouts are recorded in UART_Last_Error_Message and stop at the failing operation.

UART_Write(Serial, "Hello from Loom!\n")
UART_Write_Byte(Handle: UART_Handle, Value: Signed_64)

Writes one byte; the value must be in the range 0 through 255.

UART_Write_Byte(Serial, 65)
UART_Byte_Available(Handle: UART_Handle) → Boolean

A data-availability query. False means the receive FIFO currently has no byte.

If (UART_Byte_Available(Serial))
UART_Read_Byte(Handle: UART_Handle) → Signed_64

Nonblocking read. Returns -1 if no byte is available; use the availability query when an empty read is not useful.
