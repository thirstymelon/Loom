Compiler & targets

How a Loom program becomes machine code, and what the native target supports.

Pipeline

The compiler is C++17 on top of LLVM. Source files pass through five stages:

  1. Lexer turns text into tokens, including interpolated strings.
  2. Parser builds the AST and instantiates generic records and blocks by monomorphization.
  3. Analyzer checks types, control flow, module visibility and safety rules.
  4. Constant evaluator folds compile-time expressions.
  5. Generator lowers to LLVM IR, then LLVM optimizes and emits an object file.

--opt-report prints what the optimizer did, such as bounds checks removed or loops vectorized.

Safety model

  • Strong static typing with no implicit numeric conversion.
  • Runtime bounds checks on arrays, slices, vectors and strings, with static elimination where provable.
  • Wrapping integer overflow, defined rather than undefined.
  • Raw pointers and manual Allocate/Release are not checked for lifetime. Memory safety is up to the programmer.

Targets

TargetNotes
Native (macOS Apple Silicon arm64, x86_64, Linux)Full language: vectors, text, hash maps, tasks, file I/O, block pointers, dynamic allocation, SIMD/AIML primitives.

Freestanding AArch64Emits freestanding ELF and flat binary with identity mapping support for bare-metal kernels.
