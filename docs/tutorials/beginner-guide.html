Beginner guide to Loom

A friendly, step-by-step introduction to systems programming in Loom. No prior low-level programming experience required. Every lesson introduces a core concept with clear analogies, a complete copy-pasteable program, line-by-line explanations, common beginner gotchas, and hands-on exercises.

How to practice along: In your terminal, create a learning workspace with loom new LearningLoom, open src/main.loom in your editor, replace its content with the lesson code, and run it with loom run. Your lesson progress is automatically saved in this browser!

1. Hello, World & Program Anatomy

Every Loom program is built from two foundational building blocks: Modules and Blocks.

The Mental Model: Think of a Module as the label on a file folder—it tells the compiler which unit this file belongs to. Think of a Block as a recipe—a self-contained procedure that carries out a sequence of actions. In every executable Loom program, execution starts at a special block named Block Main.

Module Main

Block Main
Implements
    Write("Hello, Loom!")
End Main

To run this program, save it in src/main.loom and run:

loom run

Your terminal will print:

Hello, Loom!

Line-by-Line Breakdown:

  • Module Main: Declares that this source file is part of the Main module. The module declaration is always the first statement in a .loom file.
  • Block Main: Defines the main procedure. When your program starts, the operating system jumps directly here.
  • Implements: Marks the beginning of executable statements. In Loom, variable declarations (if any) always go before Implements, keeping code structured and readable.
  • Write("Hello, Loom!"): A built-in routine that prints text to your screen and automatically starts a new line.
  • End Main: Clearly closes the block. Loom uses explicit named delimiters (like End Main and End If) instead of curly braces {} so you never lose track of which block you are closing.

Beginner Gotchas:
1. Matching block names: If you start with Block Main, you must end with End Main. Writing End Function or End Routine will result in a compiler error.
2. Capitalization: Loom keywords (Module, Block, Implements, End) start with a capital letter.

Exercise 1: Print two lines of text

Modify Block Main to print your name on the first line and your favorite programming language on the second line.

Module Main

Block Main
Implements
    Write("Hello, my name is Alex!")
    Write("I am learning Loom systems programming.")
End Main

2. Variables, Types and Literals

Computers process data by storing numbers and text in memory. To keep track of this data, we use variables.

The Mental Model: A variable is a labeled storage box. In Loom, you must declare what type of box you need in the Declares section before using it in Implements. This ensures zero surprises, zero hidden type conversions, and maximum performance.

Module Main

Block Main
Declares
    Age    : Signed_32
    Score  : Float_64
    Active : Boolean
    Grade  : Character
Implements
    Age = 25
    Score = 98.5
    Active = True
    Grade = 'A'
    Write("Age: , Score: , Active: , Grade: ")
End Main

Running this prints:

Age: 25, Score: 98.5, Active: True, Grade: A

Core Types at a Glance:

TypeBitsWhat it storesExample Values

Unsigned_32 (or Uint32)32-bitPositive whole numbers only (0 to 4.29 billion)0, 25, 0xFF_AA
Float_64 (or Float64)64-bitDecimal / fractional numbers3.14159, -0.001
Boolean (or Bool)1-bitTrue or False logicTrue, False
Character (or Char)32-bitA single Unicode character'A', 'z', '9'

Helpful Syntax Features:

  • Digit separators: You can insert underscores into large numbers for readability: 1_000_000 or 0b0100_1101. The compiler ignores the underscores.
  • String interpolation: Inserting <VariableName> inside a string automatically converts and prints the variable's value!

Beginner Gotchas:
1. Zero-Initialization: In Loom, if you declare a variable but do not assign it a value, it is automatically initialized to zero (or False for booleans). You never get random garbage memory.
2. Unsigned numbers: An Unsigned_32 cannot hold negative values. Trying to assign -5 to an unsigned type triggers a compile-time error.

3. Math, Operators & In-Place Updates

Loom provides a full set of arithmetic, comparison, and logical operators for calculations.

The Mental Model: Arithmetic operators calculate new values. Compound mutator operators (like += and -=) update an existing variable in-place without having to re-type the variable name.

Module Main

Block Main
Declares
    Price    : Signed_32
    Discount : Signed_32
    Final    : Signed_32
    Is_Cheap : Boolean
Implements
    Price = 100
    Discount = 15
    Final = Price - Discount
    Final += 5                # Add $5 shipping fee in-place
    Is_Cheap = (Final < 100) And (Final > 0)
    Write("Final price: , Is cheap: ")
End Main

Running this prints:

Final price: 90, Is cheap: True

Operators Summary:

CategorySymbolsMeaning & Example
Arithmetic+, -, *, /, ModAddition, Subtraction, Multiplication, Division, Remainder (10 Mod 3 is 1).
Compound Mutators+=, -=, *=, /=In-place update: X += 5 is identical to X = X + 5.
Comparisons==, !=, <, <=, >, >=Checks equality, inequality, and magnitude. Returns a Boolean.
LogicalAnd, Or, NotCombines conditions: (A > 0) And (B > 0).
Bitwise Operations&, |, ^, ~, LSL, LSRAND, OR, XOR, NOT, Logical Shift Left/Right (essential for embedded registers).

Beginner Gotchas:
1. Equality vs Assignment: Use double equals == to check if two values are equal. Use a single equals = to assign a value to a variable.
2. Integer division: Dividing two integers truncates any fraction towards zero: 7 / 2 equals 3. To preserve decimals, use Float_64.

Exercise 3: Calculate rectangle perimeter and area

Declare Width : Signed_32 = 8 and Height : Signed_32 = 5. Compute Area = Width * Height and Perimeter = 2 * (Width + Height), then display both.

Module Main

Block Main
Declares

    Height    : Signed_32 = 5
    Area      : Signed_32
    Perimeter : Signed_32
Implements
    Area = Width * Height
    Perimeter = 2 * (Width + Height)
    Write("Area: , Perimeter: ")
End Main

4. Making Decisions with If, Else If, and Else

Programs become powerful when they can make decisions and choose different actions based on data.

The Mental Model: Think of an If statement as a fork in the road: "If the traffic light is green, proceed. Else if it is yellow, slow down. Else, stop."

Module Main

Block Main
Declares
    Score : Signed_32
Implements
    Score = 85

    If (Score >= 90)
        Write("Grade: A - Outstanding!")
    Else If (Score >= 80)
        Write("Grade: B - Great job!")
    Else If (Score >= 70)
        Write("Grade: C - Passing.")
    Else
        Write("Grade: F - Try again.")
    End If
End Main

Running this prints:

Grade: B - Great job!

Rules for Decision Blocks:

  • The condition inside If (...) must evaluate strictly to a Boolean (True or False).
  • You can chain multiple Else If checks one after another.
  • The optional Else block acts as a catch-all if none of the preceding conditions were met.
  • Every If block must conclude with an explicit End If.

Beginner Gotchas:
1. Strict Booleans: In languages like C or JavaScript, you can write if (count). In Loom, conditions must be explicit: write If (Count != 0).
2. Closing delimiter: Don't forget End If at the end of your conditional branch!

Exercise 4: Temperature check

Write an If statement that checks a Temp : Signed_32 variable. If Temp <= 0, print "Freezing". If Temp >= 100, print "Boiling". Otherwise print "Normal liquid".

Module Main

Block Main
Declares
    Temp : Signed_32 = -5
Implements
    If (Temp <= 0)
        Write("Freezing water (Ice)")
    Else If (Temp >= 100)
        Write("Boiling water (Steam)")
    Else
        Write("Normal liquid water")
    End If
End Main

5. Repeating Work with Loops

When you need to repeat statements multiple times, you use a loop.

The Mental Model: Loom provides three clear ways to loop:
1. Loop while (condition): Keep repeating as long as a condition remains True.
2. Loop until (condition): Keep repeating until a target condition becomes True.
3. Loop ... End Loop: An infinite loop that repeats forever unless you break out with Exit.

Module Main

Block Main
Declares
    Count : Signed_32
Implements
    Write("Counting up with while:")
    Count = 1
    Loop while (Count <= 5)
        Write("Step: ")
        Count += 1
    End Loop

    Write("Counting down with until:")
    Loop until (Count <= 1)
        Count -= 1
        Write("Down to: ")
    End Loop
End Main

Running this prints:

Counting up with while:
Step: 1
Step: 2
Step: 3
Step: 4
Step: 5
Counting down with until:
Down to: 4
Down to: 3
Down to: 2
Down to: 1

Controlling Loops:

  • Exit: Immediately breaks out of the loop and continues with the rest of the program.
  • Skip: Skips the rest of the current iteration and jumps directly to the next loop check.

Beginner Gotchas:
1. Lowercase loop keywords: In Loom, while and until are strictly lowercase keywords (e.g. Loop while (...)).
2. Remember to increment: If you forget Count += 1 inside a while loop, the condition will never become false and your program will loop forever!

Exercise 5: Print even numbers from 2 to 10

Write a while loop that starts at 2 and prints every even number up to 10.

Module Main

Block Main
Declares
    Num : Signed_32 = 2
Implements
    Loop while (Num <= 10)
        Write("Even number: ")
        Num += 2
    End Loop
End Main

6. Procedures, Functions & Concise Routines

As programs grow, writing all code inside Block Main becomes unmanageable. We organize code into reusable Blocks (functions and procedures).

The Mental Model: A block is like a machine:
• Takes: What materials (parameters) go into the machine.
• Produces: What finished product (return type) comes out.
• Give: The action of handing the finished product back to the caller.

Module Main

Block Double_Number
    Takes
        X : Signed_32
    Produces Signed_32
    Declares
        Ans : Signed_32
    Implements
        Ans = X * 2
        Give Ans
End Double_Number

Block Add_Fast
    Takes
        A : Signed_32
        B : Signed_32
    Produces (A + B)
End Add_Fast

Block Main
Declares
    Val1 : Signed_32
    Val2 : Signed_32
Implements
    Val1 = Double_Number(21)
    Val2 = Add_Fast(15, 25)
    Write("Val1: , Val2: ")
End Main

Running this prints:

Val1: 42, Val2: 40

Key Concept: Concise One-Line Routines: Notice Block Add_Fast. When a routine's entire body is simply computing and returning a value, Loom allows writing Produces (<Expr>) directly on the signature line! This eliminates boilerplate while retaining complete static type safety.

Beginner Gotchas:
1. Direct Calling: Call blocks directly by their name: Result = Double_Number(21). Do not write Call Double_Number(...).
2. Returning Values: If a block specifies Produces <Type>, you must return a value using Give <Expr>.

Exercise 6: Write a Multiply block

Create a block named Multiply that takes two Signed_32 numbers and returns their product using concise syntax.

Module Main

Block Multiply
    Takes
        A : Signed_32
        B : Signed_32
    Produces (A * B)
End Multiply

Block Main
Implements
    Write("5 * 8 = ")
End Main

7. Grouping Data with Records & Enums

Real-world software needs to bundle related data together—for example, an (X, Y) coordinate, a user account, or a sensor reading. In Loom, we use Records and Enums.

The Mental Model:
• A Record is a custom compound type that groups multiple fields together.
• An Enum is a set of distinct, named options (like states: Idle, Active, Offline).
• A Match ... When statement compares a value against all possible cases cleanly.

Module Main

Record Point
    X : Signed_32
    Y : Signed_32
End Point

Enum Status : Unsigned_8
    Idle = 0
    Active = 1
    Offline = 2
End Status

Block Main
Declares
    Player : Point = Point{ X: 50, Y: 100 }
    State  : Status
Implements
    Player.X += 10
    Write("Player at: (, )")

    State = Status.Active
    Match State
        When Status.Idle:
            Write("Status: Standing by")
        When Status.Active:
            Write("Status: In motion!")
        Else:
            Write("Status: Disconnected")
    End Match
End Main

Running this prints:

Player at: (60, 100)
Status: In motion!

Key Observations:

  • Instantiate records using struct literal syntax: Point{ X: 50, Y: 100 }.
  • Access or mutate record fields using dot notation: Player.X += 10.
  • Pattern matching with Match ... When provides a clean alternative to long If/Else ladders, with an Else: case to catch all other values.

Beginner Gotchas:
1. Enum Namespacing: When referencing enum values, always prefix them with the enum name: Status.Active, not just Active.
2. Match Fallback: Always include an Else: clause in Match to ensure every possible state is safely handled.

Exercise 7: Create a 3D coordinate record

Create a Record Point3D containing X, Y, and Z fields, instantiate it at (10, 20, 30), and print the coordinates.

8. Lists of Data with Arrays (1-Based Indexing)

When you have a collection of items (like a list of high scores or a series of temperature readings), storing them in individual variables like Score1, Score2, Score3 is cumbersome. We use Arrays.

The Natural Human Counting Model:

Most older programming languages (C, Java, Python) count arrays starting at zero: the first item is [0], and in an array of 4 items, the last item is [3]. This zero-offset model causes the infamous "off-by-one" bug for beginners.

Loom uses 1-based natural human indexing:

  • The first element is at index 1: Scores[1].
  • The second element is at index 2: Scores[2].
  • The last element is at index Length: Scores[Scores.Length]!
Module Main

Block Main
Declares
    Scores : Signed_32 Array[4]
    I      : Unsigned_64
    Sum    : Signed_32
Implements
    Scores[1] = 90
    Scores[2] = 85
    Scores[3] = 95
    Scores[4] = 100

    Sum = 0
    I = 1
    Loop while (I <= Scores.Length)
        Sum += Scores[I]
        I += 1
    End Loop

    Write("Total sum: , Length: ")
End Main

Running this prints:

Total sum: 370, Length: 4

Runtime Bounds Trapping: If your code ever tries to read Scores[0] or Scores[5], Loom will immediately halt with a hardware bounds trap. In Loom, out-of-bounds memory accesses can never silently corrupt memory!

9. Memory Addresses, Pointers & Guaranteed Cleanup (Ensure)

Loom gives you direct control over hardware memory while keeping code expressive and safe.

The Mailbox Analogy for Pointers:

  • A variable is a house. Inside the house is a value (e.g. 42).
  • Every house has a physical street address (e.g. 0x7ffee4).
  • A Pointer is a piece of paper that holds that address.
  • Address(Variable) writes down the street address of the variable onto your paper.
  • Deref(Pointer) visits that address and reads or modifies the contents of the house!

The Kitchen Stove Analogy for Ensure:

Imagine cooking dinner. Whether you finish the recipe normally or have to rush out of the house because an alarm went off, you must always turn off the stove. In Loom, Ensure { ... } guarantees that cleanup code runs automatically when leaving a block, in reverse order (LIFO: Last-In, First-Out).

Module Main

Block Work_With_Safety
Declares
    Val : Signed_32 = 10
    Ptr : Signed_32 Pointer = Address(Val)
Implements
    Ensure { Write("Cleanup: Powering down sensor (runs last)") }
    Ensure { Write("Cleanup: Closing file handle (runs first)") }

    Write("Initial value: ")
    Deref(Ptr) = 99
    Write("Modified via pointer: ")
    Write("Finishing work...")
End Work_With_Safety

Block Main
Implements
    Work_With_Safety()
End Main

Running this prints:

Initial value: 10
Modified via pointer: 99
Finishing work...
Cleanup: Closing file handle (runs first)
Cleanup: Powering down sensor (runs last)

Beginner Gotchas:
1. Reverse LIFO order: Notice that "Closing file handle" ran before "Powering down sensor". Ensure statements always unwind in reverse order of how you registered them.
2. Null Safety: If a pointer is Null, it points to nowhere. Always verify If (Ptr != Null) before calling Deref(Ptr).

Exercise 9: Safely double a number via a pointer

Create a variable with value 50, get its address, and double the value through the pointer using Deref.

Module Main

Block Main
Declares

    Ptr : Signed_32 Pointer = Address(Num)

10. Organizing Projects with Modules & Namespaces

Congratulations! You have reached the final lesson. In real-world software engineering, projects span multiple files. Loom organizes multi-file projects cleanly with Modules.

The Mental Model:

Every Loom file defines a module. To use routines from another file:
1. Import Math: Gives you access to routines using the module prefix (e.g. Math.Add(...)).
2. use Math: Brings routines directly into your local scope so you can simply call Add(...) without prefixes!

File 1: src/math.loom

Module Math

Block Add
    Takes
        A : Signed_32
        B : Signed_32
    Produces (A + B)
End Add

File 2: src/main.loom

Module Main

Import Math
use Math

Block Main
Implements
    # Calling with module prefix:
    Write(Math.Add(10, 20))

    # Calling directly because of 'use Math':
    Write(Add(5, 5))
End Main

Running this prints:

30
10

Beginner Gotchas:
1. File naming: Make sure your file name matches the module name (e.g. src/math.loom declares Module Math).
2. Scoping of 'use': A use statement placed outside blocks applies to the entire file. A use statement placed inside a block is local to that block only.
