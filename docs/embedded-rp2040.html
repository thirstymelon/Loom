Bare-Metal Systems & Embedded Hardware

Bare-metal RP2040 development

Write high-performance bare-metal firmware for the Raspberry Pi RP2040 (Raspberry Pi Pico) using Loom and the Loom SDK. No operating system, zero hidden runtime overhead, and direct register control.

The RP2040 microcontroller architecture

The Raspberry Pi RP2040 is a modern 32-bit dual-core microcontroller engineered by Raspberry Pi. Loom compiles bare-metal code directly to the ARM Cortex-M0+ architecture using LLVM target thumbv6m-none-eabi with CPU cortex-m0plus:

Hardware FeatureSpecification & Architecture Details
Processor CoresDual-core ARM Cortex-M0+ running at up to 133 MHz (standard clock 125 MHz).
Memory Map (SRAM)264 KB on-chip SRAM divided into 6 independent banks, mapped at base 0x20000000.
External Flash (XIP)Execute-In-Place (XIP) QSPI Flash interface mapped at base 0x10000000 (typically 2 MB).
Peripherals & SIOSingle-cycle IO (SIO) bus mapped at 0xD0000000 for sub-nanosecond GPIO manipulation; APB/AHB peripherals at 0x40000000.

Creating a bare-metal project

Scaffold a clean, bare-metal RP2040 workspace with zero local boilerplate using the --rp2040 flag:

loom new PicoBlink --rp2040
cd PicoBlink

Notice that no local assembler files, linker scripts, or BSP sources clutter your repository. The project contains only your source and configuration:

Project FileDescription & Role
config.tomlConfigured with baremetal = true, target thumbv6m-none-eabi, CPU cortex-m0plus, and uf2-output = true.
src/main.loomFirmware entry point importing peripheral modules from the Loom SDK.
wokwi.toml & diagram.jsonPreconfigured instant simulation environment for VS Code and headless Wokwi CLI.
README.md & .gitignoreBuild, flash, and simulation instructions.

The Loom SDK architecture

Loom ships with a pre-verified Hardware Abstraction Layer (HAL), second-stage bootloader, and linker script installed system-wide at /usr/local/share/loom/sdk/:

SDK PathTechnical Function
targets/rp2040/boot.sStage-2 bootloader (boot2 with 256-byte CRC32 header) configured for W25Q080 QSPI Flash, full ARM Cortex-M0+ vector table (Reset, NMI, HardFault, SysTick), stack initialization, flash-to-RAM .data segment copying, and .bss zeroing.
targets/rp2040/linker.ldBare-metal memory map configuring 2 MB Flash (0x10000000) and 264 KB SRAM (0x20000000), section alignments, and initial stack pointer placement at the top of RAM (0x20042000).
targets/rp2040/bsp/Pre-compiled Loom hardware abstraction modules (RP2040, System, Clock, GPIO, Time, UART, SPI, I2C, ADC, PWM, DMA, Watchdog, Multicore, PIO, RTC, Interp).
std/Loom standard library: math.loom (standard mathematical routines).

Resolution Order: loom build searches your local project directory first, then checks /usr/local/share/loom/sdk/ or $LOOM_SDK_PATH. To customize a hardware driver, simply place a file named src/bsp/gpio.loom in your project, and it will override the SDK default.

Hardware Abstraction Layer (HAL) modules

The Loom SDK provides clean, zero-overhead modular HAL components for controlling every hardware peripheral on the RP2040:

1. Master Umbrella Module (RP2040)

  • RP2040_Init(): High-performance initialization configuring 12 MHz XOSC, tuning PLL_SYS to 125 MHz, PLL_USB to 48 MHz, clk_adc to 48 MHz, clk_rtc to 46875 Hz, enabling hardware timers, initializing UART0 at 115200 baud, and unresetting all core peripherals.
  • RP2040_Init_Minimal(): Fast lightweight boot directly on 12 MHz XOSC without PLL lock wait times, suitable for low-power or minimalist firmware.
  • Import RP2040 / use RP2040: Transitive imports grant immediate access to all peripheral drivers with a single line.

2. Module System (System)

  • System_Init(): Initializes crystal oscillator (XOSC), switches reference clocks, and unresets timers.
  • Unreset_Peripherals(Mask : Unsigned_32): Atomically clears reset bits for selected peripherals and polls until operational.
  • Reset_Peripherals(Mask : Unsigned_32): Asserts hardware reset on target peripheral blocks.
  • Is_Peripheral_Ready(Mask : Unsigned_32): Returns True when all masked peripherals are out of reset.
  • System_Reset(): Performs a deterministic software chip reboot via ARM Cortex-M0+ AIRCR sysresetreq and Watchdog trigger.
  • Get_Chip_Revision() / Get_Chip_Part() / Is_ASIC_Platform(): Hardware silicon identification via SIO CHIP_ID and PLATFORM registers.

3. Module Clock (Clock)

  • Clock_Init(): Configures complete standard RP2040 clock tree: 125 MHz system clock, 125 MHz peripheral clock, 48 MHz USB clock, 48 MHz ADC clock, and 46875 Hz RTC clock.
  • Clock_Set_Sys_Freq(FreqHz : Signed_64): Dynamically retunes the system clock (48 MHz, 125 MHz, 133 MHz) through glitchless muxing without crashing running code.
  • Clock_Configure(Clock_Idx, Glitchless_Src, Aux_Src, Src_Freq, Target_Freq): Full low-level clock generator configuration following the official datasheet switching protocol.
  • XOSC_Init() / XOSC_Disable() / XOSC_Is_Stable(): Controls the 12 MHz crystal oscillator with hardware startup delay counters.
  • ROSC_Set_Div(Div) / ROSC_Get_Random_Word() / ROSC_Get_Random_Bit(): Controls ring oscillator and extracts true hardware entropy (TRNG) from physical ring oscillator jitter.
  • PLL_Init(Pll_Idx, RefDiv, FbDiv, PostDiv1, PostDiv2) / PLL_Sys_Init_125Mhz() / PLL_Usb_Init_48Mhz(): Precision integer and fractional PLL synthesis.
  • Clock_Frequency_Count_Khz(FcSrc) / Clock_Frequency_Count_Mhz(FcSrc): Hardware frequency measurement via FC0 counter against reference crystal.
  • Clock_Resus_Enable(Cycles) / Clock_Resus_Has_Triggered() / Clock_Resus_Clear(): Clock resuscitation watchdog that auto-switches to backup clock if PLL fails.
  • Clock_Gpio_Init(GpioPin, ClkSrc, Div): Outputs internal clock signals to GPIO pins (GPIO 21, 23, 24, 25).

4. Module GPIO (GPIO)

  • Init_Pin(Pin : Signed_64): Configures a pin for Single-Cycle IO (SIO function 5).
  • Set_Function(Pin : Signed_64, Func : Signed_64): Maps pin to hardware functions (SPI, UART, I2C, PWM, SIO, PIO0, PIO1, USB).
  • Set_Direction(Pin : Signed_64, Direction : Signed_64): Sets pin mode to PIN_OUTPUT (1) or PIN_INPUT (0).
  • Set_High(Pin : Signed_64) / Set_Low(Pin : Signed_64): Drives pin state high (3.3V) or low (0V) in a single CPU cycle.
  • Toggle(Pin : Signed_64): Inverts the current logic state of the pin.
  • Read_Pin(Pin : Signed_64): Reads digital input state, returning 0 or 1.
  • Set_Pull(Pin : Signed_64, Pull : Signed_64): Configures pull-up (PULL_UP), pull-down (PULL_DOWN), or floating (PULL_NONE).
  • Set_Drive_Strength(Pin : Signed_64, Drive : Signed_64): Configures output drive current (2mA, 4mA, 8mA, 12mA).
  • Set_Slew_Rate(Pin : Signed_64, Fast : Boolean) / Set_Schmitt_Trigger(Pin : Signed_64, Enable : Boolean): Configures pad slew rate and hysteresis.
  • Set_Pins_Mask(Mask : Unsigned_32) / Clear_Pins_Mask(Mask : Unsigned_32): Atomic multi-pin port manipulation.
  • Enable_Pin_Interrupt(Pin : Signed_64, Events : Signed_64) / Clear_Pin_Interrupt(Pin : Signed_64, Events : Signed_64): Pin edge/level interrupt configuration and clearing on default Core 0.
  • Enable_Pin_Interrupt_Core(CoreId : Signed_64, Pin : Signed_64, Events : Signed_64) / Get_Pin_Interrupt_Status_Core(...): Independent dual-core GPIO interrupt routing for Core 0 or Core 1.

5. Module Time (Time)

  • Get_Time_Microseconds(): Reads the RP2040 64-bit 1 MHz hardware timer directly and safely using non-latching registers.
  • Get_Time_64_Microseconds(): Thread-safe, multi-core safe non-latching atomic 64-bit microsecond counter read via TIMERAWH and TIMERAWL.
  • Get_Time(): Returns current board uptime in milliseconds.
  • Delay_Microseconds(Microseconds : Signed_64) / Delay(Milliseconds : Signed_64): Busy-wait delay calibrated to hardware clock.
  • SleepUs(Microseconds : Signed_64) / SleepMs(Milliseconds : Signed_64): Precision sleep helpers.
  • Set_Alarm_Target(AlarmId : Signed_64, TargetUs : Signed_64) / Set_Alarm_Delay(AlarmId : Signed_64, DelayUs : Signed_64): Arms hardware alarms 0–3.
  • Is_Alarm_Armed(AlarmId : Signed_64) / Disarm_Alarm(AlarmId : Signed_64) / Clear_Alarm_Interrupt(AlarmId : Signed_64): Hardware alarm polling, disarming, and interrupt clearing.

6. Module UART (UART)

  • UART_Init(Baud_Rate : Signed_64): Configures default UART0 on GPIO 0 (TX) and GPIO 1 (RX) with line control (8 data bits, no parity, 1 stop bit, FIFOs enabled) automatically sensing peripheral clock.
  • UART_Init_Channel(Channel : Signed_64, Baud_Rate : Signed_64, PinTx : Signed_64, PinRx : Signed_64): Configures either UART0 or UART1 with custom pin assignments and fractional baud rate divisor.
  • UART_Set_Baud_Rate(Uart_Idx : Signed_64, Baud_Rate : Signed_64, Peri_Clock_Hz : Signed_64): Dynamically recalibrates integer and fractional baud divisors for any peripheral clock.
  • Write_UART(Msg : String): Serial string output with automatic newline handling.
  • Write_UART_Byte(B : Signed_64) / Read_UART_Char(): Single-byte FIFO write and blocking read.
  • UART_Available() / UART_Is_Writable(): Checks receive FIFO depth and transmit FIFO headroom.

7. Module SPI (SPI)

  • SPI_Init(BaudRate : Signed_64): Configures default SPI0 at target baud rate (GPIO 16 MISO, 19 MOSI, 18 SCK) automatically adapting to peripheral clock.
  • SPI_Init_Channel(Channel : Signed_64, BaudRate : Signed_64, PinRx : Signed_64, PinTx : Signed_64, PinSck : Signed_64): Initializes SPI0 or SPI1 with custom pin muxing.
  • SPI_Set_Baud_Rate(Spi_Idx : Signed_64, Baud_Hz : Signed_64, Peri_Clock_Hz : Signed_64): Computes even prescale and serial clock dividers for exact target frequencies.
  • SPI_Set_Format(Channel : Signed_64, DataBits : Signed_64, Cpol : Signed_64, Cpha : Signed_64): Configures Motorola SPI Modes 0, 1, 2, or 3 and word size (4 to 16 bits).
  • SPI_Write_Byte_Ch(Channel : Signed_64, Data : Signed_64) / SPI_Read_Byte_Ch(Channel : Signed_64): Single-word blocking transmission and reception.
  • SPI_Transfer_Byte_Ch(Channel : Signed_64, Data : Signed_64): Full-duplex simultaneous write/read.
  • SPI_Write_Slice(Channel : Signed_64, Data : Unsigned_8 Slice) / SPI_Read_Slice(...): High-throughput buffer streaming via fat slices.

8. Module I2C (I2C)

  • I2C_Init(SpeedHz : Signed_64): Configures default I2C0 on GPIO 4 (SDA) and GPIO 5 (SCL) in standard (100 kHz) or fast (400 kHz) mode.
  • I2C_Init_Channel(Channel : Signed_64, SpeedHz : Signed_64, PinSda : Signed_64, PinScl : Signed_64): Initializes I2C0 or I2C1 with automatic clock frequency dividers.
  • I2C_Init_Channel_Freq(...): Uses exact datasheet timing equations to synthesize SCL High and Low counts dynamically for any system clock frequency.
  • I2C_Write_Byte_Direct(Channel : Signed_64, Addr : Signed_64, Val : Signed_64, Stop : Boolean): Transmits a single byte to a 7-bit slave address.
  • I2C_Read_Byte_Direct(Channel : Signed_64, Addr : Signed_64, Stop : Boolean): Receives a single byte from a 7-bit slave address.
  • I2C_Write_Slice(...) / I2C_Read_Slice(...): Multi-byte block transfers with configurable STOP condition.
  • I2C_Write_Register_8(...) / I2C_Read_Register_8(...): Sensor register transactions.

9. Module ADC (ADC)

  • ADC_Init(): Powers up the 12-bit ADC, verifies active ADC clocking, and enables onboard temperature sensor.
  • ADC_Init_Pin(Pin : Signed_64): Disables digital pad buffers on GPIO 26–29 to eliminate leakage during analog sampling.
  • ADC_Select_Input(Channel : Signed_64): Selects the active multiplexer input channel (0–3 for GPIO 26–29, 4 for temperature sensor).
  • Read_ADC_Raw(Channel : Signed_64): Reads 12-bit conversion result (0–4095).
  • Read_ADC_Millivolts(Channel : Signed_64): Converts reading to calibrated millivolts.
  • Read_Temperature_Celsius() / Read_Temperature_Millicelsius(): Computes onboard temperature using official RP2040 datasheet $V_{BE}$ conversion curve.

10. Module PWM (PWM)

  • PWM_Init(Pin : Signed_64): Assigns a GPIO pin to its hardware PWM slice (channels 0–7) with 16-bit TOP wrap (65535).
  • PWM_Set_Clock_Div(Pin : Signed_64, IntegerPart : Signed_64, FracPart : Signed_64): Fine-grained clock prescaler control.
  • PWM_Set_Wrap(Pin : Signed_64, Wrap : Signed_64): Configures custom counter reload period (TOP).
  • PWM_Set_Enabled(Pin : Signed_64, Enabled : Boolean): Starts or halts an individual PWM counter slice.
  • PWM_Set_Mask_Enabled(Mask : Unsigned_32): Atomically starts or stops multiple PWM slices simultaneously.
  • Set_PWM_Raw(Pin : Signed_64, Level : Signed_64): Directly sets the compare level (0–TOP).
  • Set_PWM_Duty(Pin : Signed_64, Percent : Signed_64): Sets duty cycle by percentage (0–100%).

11. Module DMA (DMA)

  • DMA_Init(): Unresets the 12-channel Direct Memory Access controller.
  • DMA_Channel_Configure(...): Configures transfer size (8, 16, or 32-bit), source/destination address increments, peripheral DREQ pacing, and channel chaining.
  • DMA_Channel_Set_Read_Addr(...) / DMA_Channel_Set_Write_Addr(...) / DMA_Channel_Set_Trans_Count(...): Dedicated address and count setters.
  • DMA_Channel_Start(Channel : Signed_64): Initiates asynchronous data transfer on a single channel.
  • DMA_Start_Multi_Channel(Mask : Unsigned_32): Atomically triggers simultaneous transfers across multiple DMA channels.
  • DMA_Channel_Is_Busy(Channel : Signed_64) / DMA_Channel_Wait_Blocking(Channel : Signed_64): Transfer polling and blocking synchronization.
  • DMA_Memcpy_32(DestAddr : Signed_64, SrcAddr : Signed_64, WordCount : Signed_64): High-speed hardware-accelerated memory block copies.

12. Module Watchdog (Watchdog)

  • Watchdog_Enable(TimeoutMs : Signed_64, PauseOnDebug : Boolean): Configures and arms the hardware watchdog timer (up to 8,388 ms).
  • Watchdog_Feed(): Reloads the watchdog counter.
  • Watchdog_Caused_Reboot(): Detects if the previous reset was triggered by a watchdog countdown expiration.
  • Watchdog_Set_Scratch(RegIndex : Signed_64, Value : Unsigned_32) / Watchdog_Get_Scratch(...): Non-volatile scratch registers 0–7 surviving soft resets.
  • Watchdog_Reboot_To_Bootsel(): Soft-reboots microcontroller directly into USB BOOTSEL mass-storage flashing mode without unplugging.

13. Module Multicore (Multicore)

  • Get_Core_Num(): Returns current CPU core (0 or 1).
  • Spinlock_Claim(LockIndex : Signed_64) / Spinlock_Release(LockIndex : Signed_64): 32 atomic hardware spinlocks providing single-cycle inter-core mutex synchronization.
  • Spinlock_Try_Claim(LockIndex : Signed_64): Non-blocking spinlock attempt returning True if acquired.
  • Multicore_FIFO_Push_Blocking(Data : Unsigned_32) / Multicore_FIFO_Pop_Blocking(): Inter-core mailbox FIFO message queues.
  • Multicore_Launch_Core1(EntryAddr : Signed_64, StackTop : Signed_64): Bootrom handshake sequence launching Core 1 execution.

14. Module PIO (PIO)

  • PIO_Init(PioIndex : Signed_64): Unresets PIO0 or PIO1 programmable I/O subsystem.
  • PIO_Load_Instruction(PioIndex : Signed_64, Offset : Signed_64, Instr : Unsigned_16): Loads raw instructions into the 32-instruction shared memory.
  • PIO_Load_Program(...): Streams complete state machine microcode programs via slices.
  • PIO_SM_Init(...) / PIO_SM_Set_Clock_Div(...) / PIO_SM_Set_Enabled(...): Initializes and controls execution for any of the 8 state machines.
  • PIO_SM_Push_Blocking(...) / PIO_SM_Pull_Blocking(...): Direct data exchange with state machine TX and RX FIFOs.

15. Module RTC (RTC)

  • RTC_Init(): Configures reference clock 1 Hz dividers and starts the hardware Real-Time Clock calendar.
  • RTC_Set_DateTime(Year, Month, Day, DayOfWeek, Hour, Minute, Second): Sets calendar date and time.
  • RTC_Get_Year(), RTC_Get_Month(), RTC_Get_Day(), RTC_Get_Hour(), RTC_Get_Minute(), RTC_Get_Second(): Reads atomic calendar values.
  • RTC_Is_Running(): Verifies active RTC oscillator tracking.

16. Module Interp (Interp)

  • Dual SIO hardware interpolators (INTERP_0 and INTERP_1) featuring two simultaneous calculation lanes (LANE_0 and LANE_1) and shared BASE2 register.
  • Interp_Set_Accum(...) / Interp_Add_Accum(...) / Interp_Set_Base(...) / Interp_Set_Base_2(...) / Interp_Set_Base_1And0(...): Configures accumulator registers, lane bases, and packed base registers.
  • Interp_Set_Config(...): Configures bit shifts, masks, and signed clamping.
  • Interp_Peek_Result(...) / Interp_Pop_Result(...): Instant hardware evaluation with automatic writeback for affine texture mapping, audio synthesis, and fixed-point stepping.
  • Interp_Peek_Combined(...) / Interp_Pop_Combined(...): Simultaneous multi-lane evaluation for 2D coordinate generation.

Complete Blink & UART heartbeat firmware

Here is the complete firmware generated in src/main.loom:

Module Main

Import System
Import GPIO
Import Time
Import UART

use System
use GPIO
use Time
use UART

Block Global
Declares
    LED_PIN : Constant Signed_64 = 25
End Global

Block Main
Implements
    System_Init()
    Init_Pin(LED_PIN)
    Set_Direction(LED_PIN, PIN_OUTPUT)
    UART_Init(115200)

    Write_UART("=================================\n")
    Write_UART("Raspberry Pi Pico initialized!\n")
    Write_UART("=================================\n")

    Loop
        Toggle(LED_PIN)
        Write_UART("Heartbeat at uptime: <Get_Time()> ms\n")
        Delay(1000)
    End Loop
End Main

Direct register access & hardware hacking

When you need to interact with hardware registers not covered by the HAL, use Loom's volatile intrinsics:

Block Read_Timer
    Produces Unsigned_32
Declares
    Ticks : Unsigned_32
Implements
    # Directly read TIMER_TIMELR register (0x4005400C)
    Ticks = Vol_Read_32(0x4005400C)
    Give Ticks
End Read_Timer

Compiling, UF2 creation & flashing

Building a bare-metal firmware project compiles the Loom sources, assembles boot.s, links with linker.ld, converts the ELF to raw binary, and packages the binary into a UF2 image:

loom build
Generated Target FilePurpose & Format
target/PicoBlink.elfStandard ELF binary containing complete symbols, debug sections, and vector tables.
target/PicoBlink.binFlat memory binary image stripped of headers.
target/PicoBlink.uf2USB Flashing format block image (512-byte blocks, family ID 0xE48FF56A) ready to drag onto the Pico.

Flashing Steps

  1. Press and hold the white BOOTSEL button on your Raspberry Pi Pico.
  2. Connect the Pico to your computer via USB, then release the button.
  3. A USB Mass Storage device named RPI-RP2 will appear in Finder / file explorer.
  4. Drag and drop target/PicoBlink.uf2 into the RPI-RP2 drive.
  5. The Pico will immediately reboot and run your firmware. The onboard LED will begin blinking, and serial heartbeat messages will stream over UART.

Hardware simulation with Wokwi

Loom projects scaffolded with --rp2040 include pre-configured Wokwi files (wokwi.toml and diagram.json). You can simulate your firmware without touching physical hardware:

  1. Open the project in VS Code with the Wokwi Simulator extension installed.
  2. Press F1 and run Wokwi: Start Simulator.
  3. The virtual Raspberry Pi Pico will boot the compiled ELF binary, flash the LED, and print messages to the built-in serial monitor.
